## 在线需求分析
现有事实已覆盖目标、流程、验收、预算、决策、权限、数据口径、故障兜底与反馈闭环，可形成若干待验证需求假设。核心瓶颈集中在三处：一是库存口径分裂（库房现存量、科室已预留量、供应商在途量）导致“系统看似够、实际调不出”，与术前缺耗材事件直接相关；二是编码与状态口径不统一（供应商码与院内码、退库未恢复可用状态），使批次追溯与过期识别缺乏可信数据基础；三是交接与留痕不足（各岗完成时间未分别记录、关键说明留在个人便签），使异常归因与验收难以成立。切入点建议优先“口径统一+批次校验+人工兜底”，因其价值直接对应缺货率与过期报废目标，且不可逆风险（来源不明耗材、批次错配）最高；补货与预留提醒可作为低风险辅助先行。需注意：覆盖率不代表验收通过，多项阈值（数据新鲜度、留存期限、停止条件判定人）尚未核实。

  推导：事实显示领用与实际使用不同日、系统库存被其他手术预留，且库房算现存量、科室算已预留量、供应商算在途量三方口径不一，临床看到够却调不出。这直接关联缺货率8%目标与术前缺一盒事件。但各节点等待与处理时间尚未分别量出，无法确认瓶颈具体落在预留还是补货环节。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：在一个手术科室回放历史领用与预留记录，按现存量/已预留量/在途量三口径逐笔比对，统计“显示可用但实际不可调”的笔数与占比；由耗材管理主任确认口径定义，采购管理员核对，作为试点前基线。
- REQ-2 编码与退库状态不统一使批次追溯与过期识别不可信
  依据：healthcare-supplies-f31、healthcare-supplies-f33、healthcare-supplies-f11、healthcare-supplies-f42
  推导：供应商商品码与院内码不统一、退库未恢复可用状态，是批次追溯最直接障碍；同时存在外包装扫码成功但内包装批次与出库批次不一致的异常。验收要求批次关联完整率100%、过期误发为零，若主编号与状态口径未定，该验收无法成立。但主编号以哪套为准、退库状态由谁确认尚未确定。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：先校验注册信息、批号、效期、手术用量与退库记录的主编号、事件时间、版本字段，歧义记录进人工修复队列；由秦芮提出主编号对齐方案，顾明岚与唐映秋确认，院感质控专员审核风险边界后再定试点样本。
- REQ-3 交接留痕缺失导致异常归因与验收指标无法成立
  依据：healthcare-supplies-f23、healthcare-supplies-f14、healthcare-supplies-f53、healthcare-supplies-f45
  推导：交接需含业务编号、版本、状态、未解决事项与接手人，仅发消息不算完成；但各岗完成时间未分别留痕，关键说明常留在个人便签或群里未随单据交接。这使投诉无法归因、改进无法证明。验收要求可重建完整处理链，当前留痕能力是否满足尚未核实。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：选取近期若干异常单，检查交接记录是否含五项要素、各岗完成时间是否可分离；由采购管理员整理样本，临床科室主任确认归因口径，形成留痕缺口清单后再定试点指标。
- REQ-4 批次异常必须人工兜底且不得覆盖原记录
  依据：healthcare-supplies-f40、healthcare-supplies-f44、healthcare-supplies-f15、healthcare-supplies-f42
  推导：红线要求批号效期与患者使用记录准确、来源不明耗材不得使用；出现内外包装批次不一致、资料缺依据、版本冲突或系统不可用须转人工并标注触发原因、接手人与确认时间。护士也明确会暂停建议由采购核对。但哪些异常必须人工复核、停止条件由谁判定尚未明确。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：用历史异常回放，逐类列出触发人工兜底的条件清单，明确每类接手人与确认时限；由院感质控专员确认停止条件判定人，耗材管理主任确认责任归属，作为试点准入前置条件。
- REQ-5 补货与预留提醒可先行，但不得自动改变临床选择
  依据：healthcare-supplies-f05、healthcare-supplies-f52、healthcare-supplies-f22、healthcare-supplies-f00
  推导：范围明确为补货与预留提醒、不自动改变临床耗材选择，首期历史回放再小范围并行试点；采购管理员权限也限于整理校核发起复核。该方向不可逆风险低、与缺货目标相关，适合作为首个可验证切入点。但提醒的准确率阈值与误报处理尚未定义。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：历史资料回放生成预留冲突提醒，统计命中与误报；由临床科室主任确认提醒是否可接受、误报如何反馈，采购管理员记录复核结果，达标后再进并行试点。
- REQ-6 数据新鲜度与故障快照边界需在试点前定清
  依据：healthcare-supplies-f34、healthcare-supplies-f35、healthcare-supplies-f32
  推导：试点计划每小时更新授权状态，超周期标待刷新；接口中断用带时间戳只读快照并显示暂未更新，重连按业务编号去重补齐。但快照只读边界（故障期能否改批次或退库状态）与验收是否测故障场景尚未核实，影响追溯结论可信度。
  判断：候选需求；需用结果与不可逆风险矩阵比较，P0/P1/P2不等于已完成价值风险评分。
  下一步：明确故障期禁止改批次与退库状态、待刷新标记的呈现与确认人；设计一次接口中断演练，检查快照时间戳、去重补齐与人工流程并行是否成立，由秦芮出方案、顾明岚确认。
